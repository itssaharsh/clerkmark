## Card
**concept:** Intake staff at a state trial court drop a self-represented litigant's filed PDF and get a one-page memo that resolves every citation against CourtListener and the opinion text and sorts each into verified, misnamed, misquoted, not in the free corpus (check Westlaw), or likely fabricated, using a deterministic rule shown on screen rather than a model's guess.

**problem:** Self-represented litigants increasingly file briefs with fabricated or misquoted authority produced by general AI assistants; 1,196 of the 2,079 court decisions in Charlotin's database involve pro se filers, and courts describe 'large judicial resources' spent tracking each citation down by hand. A free-corpus check that mislabels a real case as fabricated creates a fairness problem, since 19.9% of retrieved opinions lack usable text and many opinions sit behind paywalls.

**user:** Intake staff at a state trial court clerk's office or self-help centre (often not lawyers), or a pro se staff attorney, at the moment a self-represented motion or brief lands on the docket, before the judge reads it.

**why_it_matters:** Problem-creating change: since late 2022 (assumption on the date) free general AI assistants let self-represented filers produce plausible fake or misquoted authority at near-zero cost, so courts now face 1,196 recorded pro se hallucination cases (as of 2026-09-25) and handle them by manual lookup and escalating sanctions of $3,000 to $15,000. Enabling change: since 2024-04-16 CourtListener's free citation-lookup API resolves a block of text's citations with an explicit 'valid but not in our corpus' status, and since 2026-05-07 any account holder can use all CourtListener APIs. Tracks: Legal Automation & Workflow Innovation, Access to Justice & Civic Tech (fair treatment of pro se filers).

**core_workflow:** Upload PDF -> pdfplumber text -> eyecite extracts citations -> one CourtListener citation-lookup call (up to 250 cites) -> for each 200 hit, fetch the opinion text and rapidfuzz-match each quoted passage -> for each 404, run the decision rule: case-name search in CourtListener (hit at another citation = 'exists, wrong cite'); reporter unknown, volume out of the reporter's range, year inconsistent with the volume, or page beyond the volume = 'likely fabricated'; otherwise 'not in the free corpus: check Westlaw' -> an optional LLM call per quoted proposition returns 'supports / does not support / cannot tell', shown as advisory triage ('read these first') -> memo table with status, matching snippet and the rule that fired; export as PDF.

**technical_implementation:** Python backend (FastAPI) with eyecite (and its reporters database for reporter and volume ranges), pdfplumber, rapidfuzz, httpx against the CourtListener v4 citation-lookup and search APIs (token in env; the 60-valid-citations-per-minute throttle honoured with a small queue; every demo response cached); a single-page React or Streamlit UI showing the memo; an LLM via any provider for the advisory support judgment only, so the app runs without it. The hard part shown on camera: the decision rule that turns API statuses 200/300/404 plus name-search and reporter/volume/year checks plus quote-match scores into the classes, and the seeded evaluation table (20 citations with known ground truth) with per-class results and latency. Credit Princeton's LePhantomCite work and CourtListener in the README and claim only the difference.

**mvp_scope:** In: PDF upload, citation extraction, existence and name check, quote fuzzy-match, the 404 decision rule with the rule shown per row, memo with legend, seeded eval table, PDF export, disclaimer that the memo is a triage aid and not a finding. Out: statutes and regulations, id./supra chains, Westlaw or Lexis integration, docket integration, batch processing, the litigant-facing correction kit (stretch), pincite verdicts (report 'could not verify pincite' only), and any claim that the advisory proposition check is a verdict.

**differentiation:** Against Learned Hand (closest product, deployed in LA County): free, narrow, intake-only, applied to a filer's document rather than the tool's own drafted order, and explicit about coverage gaps with a visible rule. Against CourtListener's own web tool: it returns one 404 for a real-but-missing case and a fabricated one; the memo splits them with a stated rule and adds quote matching and a memo. Against Sigma tech (closest past winner at a comparable event): starts from a filed court PDF and a named free corpus rather than checking chat output in the browser. Against the Princeton agent: a deterministic-first memo for staff, credited, not an agent loop.

**risks:** The mechanism follows Princeton's public five-class approach and hallucinated-citation checkers are the obvious 2026 entry (the critic flagged clone and default-entry risk); the visible decision rule, the intake user and the memo are the whole claim to originality, so they must be on screen and in the README; CourtListener's default rate limit for new accounts is unstated since 2026-05-07; test it in hour 0 and cache every demo response; Misrepresented propositions are the largest error category (42.0%) and get only the advisory LLM check; present it as 'read these first', never as a verdict; Pincite verification against free text is weak (18.2% to 52.8% recall in Princeton's tests); keep it out of the headline; Learned Hand may already screen filings for hallucinations (unopened snippet); if so the wedge shrinks to 'free and narrow'; A judge may drop in a filing with statutes or id. chains that eyecite resolves poorly; the memo must say what it skipped; Mata v. Avianca is the demo every citation checker uses; mix in a real state appellate case that CourtListener lacks so the coverage-gap class visibly fires

**buildable_in_event:** A 1 to 4 student team in roughly 12 to 14 hours: hour 0-1 create a CourtListener account, make one real API call to learn the rate limit, pre-cache 12 opinion texts; hours 1-5 extraction, lookup, the 404 decision rule; hours 5-8 quote matching and memo UI; hours 8-10 seeded eval table and unhappy paths; hours 10-12 deploy (live URL), README with tool list and credits, 3-minute video. Seeded: one synthetic pro se motion mixing the six fabricated Mata v. Avianca case names with real citations and at least one real state appellate case that CourtListener lacks. Live: every API call (with cache). Mocked: nothing in the core loop; the LLM advisory step degrades to 'not run' if the key fails.

## Wedge
A free intake memo for the court staff who receive a self-represented filing: a deterministic rule (case-name search plus reporter, volume and year consistency, shown on screen) separates 'not in the free corpus: check Westlaw' from 'likely fabricated', where CourtListener's own tool returns one 404 for both, drafter-side checkers serve the filer, and Learned Hand is a paid chambers platform that verifies its own drafted orders.

## Demo
**first_10s:** "When someone without a lawyer files a brief written with a chatbot, court staff have to look up every case by hand to find the fake ones. We do that in thirty seconds, and we show the rule that tells a fake case from a real one the free database just doesn't have."
**first_minute:** Drop a 12-page pro se motion PDF. Watch 14 citations appear, the CourtListener call go out (network panel visible), and the memo fill in: 9 verified with snippets, 3 quotes not found in the opinion, 1 likely fabricated (no such reporter volume), 1 'not in the free corpus, check Westlaw'.
**wow_moment:** Two rows side by side: 'Varghese v. China Southern Airlines, 925 F.3d 1339' goes red (likely fabricated: no name hit, and volume 925 of F.3d does not match the cited year), while a real state appellate case goes amber ('not in the free corpus: reporter and volume plausible, no name hit; check Westlaw'). The rule that fired is printed under each row. A naive checker returns the same 404 for both.
**technical_depth:** Open the eval tab: the seeded 20-citation set with ground truth, per-class results, false-positive count (target: 0 real cases called fabricated), latency per stage, the raw API status codes (200/300/404) and the decision-rule branch for each 404. Show the code path for the rule.
**story:** Charlotin's database lists 2,079 decisions and 1,196 involving self-represented filers, with September 2026 sanctions of $3,000 to $15,000 (linked on screen); Princeton reports courts spending 'large judicial resources' verifying citations and warns that absence from a free corpus is not proof of fabrication.
**unhappy_path:** Paste a filing whose quote is slightly paraphrased from a real opinion: the memo returns 'quote not found verbatim; closest passage 78% similar' and shows the passage, rather than declaring fabrication. Upload a scanned image PDF: 'no text layer found; OCR not enabled in this prototype'. Turn the LLM key off: the memo still runs, with the advisory column marked 'not run'.
**judge_touches:** A live URL with the seeded motion preloaded and a 'try your own PDF' upload; readable errors; the eval tab; the repo with README (setup, API list, limits) and the seeded test set as JSON.
**moments:**
- Real-World Impact & Feasibility: The Charlotin sanction entries on screen, then the memo replacing an afternoon of lookups
- Technical Execution & Functionality: The live API call, the six-class state machine, the eval table
- User Experience & Design: One upload, one page; plain-language row labels; legend
- Innovation & Originality: The red fabricated row next to the amber coverage-gap row, each with the rule that fired
- Presentation & Documentation: A 3-minute video that ends on the limits slide and the README's tool list

## Criteria alignment
- **Real-World Impact & Feasibility** — A named user (pro se staff attorney) and a documented, growing burden (1,196 pro se hallucination cases; courts' 'large judicial resources'); a free public data source (CourtListener) that a state court could actually run; the coverage-gap class addresses the fairness risk of mislabeling real cases. Gap: No clerk was interviewed; the value for federal chambers with Westlaw is smaller.
- **Technical Execution & Functionality** — A real pipeline (extraction, API resolution, opinion fetch, fuzzy matching, class assignment) that runs end to end on camera, with a seeded 20-citation evaluation table, latency shown, and readable code structure in the repo. Gap: Rate limits or opinion texts without pagination can degrade results; show the fallback.
- **User Experience & Design** — One upload, one page of output; each citation row in plain words ('this quote does not appear in the opinion'), with the matching snippet; a visible legend for the six classes; no legal jargon beyond the citation itself. Gap: The primary user is a court professional; make the memo readable by the litigant too (the criterion asks about non-lawyers).
- **Innovation & Originality** — The court-side intake framing and the explicit 'not in the free corpus' class, where filer-side checkers return pass/fail; the on-screen contrast between a fabricated case and a real case missing from the free database. Gap: The mechanism exists in Princeton's public code; originality is in packaging and user, so say so honestly.
- **Presentation & Documentation** — A 3-minute video: the problem in 15 seconds with one real sanction entry from Charlotin's database, the live run, the eval table, the limits; README listing every API, library and model, as the rules require. Gap: None specific; keep the video under 3:00.

## Closest competitors
- Sigma tech (SMU LIT Legal-Tech Hackathon 2026, reported 2nd place): Sigma tech checks LLM chat output inside claude.ai and chatgpt.com with whitelist/graylist/blacklist layers and no named corpus; this idea takes a filed court PDF, resolves against CourtListener, matches quotes, and separates coverage gaps from fabrication for a court user.
- Learned Hand (startup): A broad, paid chambers platform (drafting, fact extraction, citation-to-source links) for judges and staff. Ours is a free, single-purpose intake triage on one pro se PDF that matches quotes and keeps 'not in the free corpus' separate from 'likely fabricated'; Learned Hand's public page does not describe checking a filer's quotes or pincites or name a corpus.
- Clearbrief, CiteSentinel, CiteCheck AI (startup): Sold to lawyers to check their own drafts (Clearbrief is LexisNexis-backed and checks quotes and holdings). Ours serves the court receiving someone else's filing and runs on a free corpus.
- Sigma tech (SMU LIT 2026) (hackathon): Checks LLM chat output in the browser with whitelist/graylist/blacklist layers and an unnamed corpus. Ours starts from a filed court PDF, uses CourtListener, matches quotes, and reports coverage gaps as their own class.
- Princeton legal-hallucination-agent and LePhantomCite (research): Same five error classes and the same CourtListener coverage problem, but it is benchmark and agent code. Ours is a deterministic-first memo for staff with the LLM only as an advisory support check; the novelty is the court user and the memo, not the algorithm.
- CourtListener Citation Lookup API and web tool (platform): Existence check only (no quotes, no pincites, no memo). Ours depends on it and adds quote and pincite matching, name-mismatch detection and the memo.
- cite-guard (oss): A 1-star repo that checks AI-drafted filings against an index (lead; repo not opened). Ours is court-side, quote-matching, with a coverage-gap class.
- Manual verification by clerks (workaround): Pull each cited case by hand on Westlaw or a free site; hours per filing (time not quantified in any source opened) and no separation of 'missing from the free database' from 'fabricated'.
